usage: awf run [options] <workflow-file> [options] [-- workflow arguments...]
       awf run [options] <workflow-file> --id <id> --continue
run options: --id <id>, --continue, --from-stage <stage>, --values <file>,
             --timeout <duration>, --run-root <directory>, --cwd <directory>, --sandbox <file>,
             --workspace <run|origin|name>, --keep-panes <never|on-failure|always>,
             --json, --no-watch, --here

Each awf run is an attempt of a run: a new run, with --id's id or a generated one, or, with
--continue, the run --id names, with the arguments, --cwd, --sandbox, --workspace and
--keep-panes it was started with. A continue reuses the stages that succeeded, up to the first
with no record or to --from-stage, and runs the rest.
A new run with --from-stage starts there. A stage before it with no record to reuse takes its
value from --values, a JSON object by stage name, checked by its result; one that returns
nothing is passed. Without one the attempt stops, naming the stage and its schema.
A run is kept in .awf/runs/<workflow>/<id> under --cwd, unless --run-root names another folder
for .awf/runs.
A run has no deadline unless --timeout gives it one, per attempt: a duration, a decimal and s, m,
h or d, such as 20m or 1d.
A workflow that knows how to present its result prints that; --json prints the full result instead.
Either way the full result is kept as out.json in the run's folder, beside report.md
when the workflow writes one. A run that fails or is cancelled once its agents have started keeps
out.json too, with what it spent and why it ended; --json prints it. A second Ctrl-C stops
awf at once, without it; a continue then reads what its agents spent.
--cwd sets the directory the workflow and its agents work in; it defaults to the current one.
--sandbox puts every agent of the run in one sandbox, working in --cwd; the file is a JSON spec
such as {"read": ["/data/request.md"], "srt": {}}, naming srt or docker, whose relative paths are
from --cwd. A workflow that opens a sandbox of its own is refused.
A sandbox with its own Herdr, as a docker box has, gets a tab in the run's workspace showing its
panes; --no-watch leaves it out, and awf still prints the command that shows them.
--workspace says where each TUI agent's tab opens: run, the run's own Herdr workspace (the
default); origin, the one awf run was typed in; or any other word, the workspace with that label,
found or made. --keep-panes says whether an agent's pane stays once it is done: never (the
default), on-failure, when its last turn wasn't answered, or always. A kept pane's harness is left
running, and yours. Both are kept with the run for every attempt, a woken one too, and win over a
workflow's deprecated layout and keepPane. A run an event started has neither, and takes the
defaults. A continue may give either again with the run's value, or its default where the run had
none, and no other.
--here, run by an agent in a Herdr pane, starts the run in a new tab and has it take that agent's
session over as one of its agents, from its next turn until the run ends. It prints a line for
the agent to end its turn with, which is how the run finds the session.
A run of a workflow with events is named by --id, or by the workflow's id(args); one without
starts may have an id made, as any run. awf run starts it with its arguments and no event,
detached in its project, as awf emit would, and the run waits at its first receive. A run already
there is only woken. A run an event starts has no argv: its args are what prepare makes of none.
Its --continue takes --from-stage, as any run's does, and no --values. A --from-stage the attempt
never reaches runs the attempt until it would park or return, and stops it there.
Exits 0 when the run completed or parked, 1 when it failed or timed out, 2 on a usage error or
when the run is refused, 3 when it stopped and can go on with --continue, and 128 plus the
signal's number when it was interrupted.

Examples:
  awf run examples/minimum-review/review-loop.ts
  awf run --timeout 20m examples/minimum-review/review-loop.ts
  awf run examples/minimum-review/review-loop.ts -- packages/engine/src
  awf run examples/minimum-review/review-loop.ts --cwd ../other-repo
  awf run examples/pane-layout/workflow.ts --workspace origin --keep-panes on-failure

Workflow files are trusted code and run with your filesystem and process authority.
