usage: awf open <run> <agent> [--no-fork] [--session <id>] [-p [<text>]]
                [--cwd <directory>] [--run-root <directory>] [--json]

A run is <workflow>/<id>, or an <id> only one workflow has, here or in a project awf knows.
Without an agent, it names the run's agents that have a session.
Opens a copy of an agent's latest session in its harness's own TUI, where the agent worked: its
working directory, its home and skills, its sandbox, on the model and effort it ran on, with the
harness's own permission prompts. The copy is made without asking the model, and is yours: the
run and the agent's session are unchanged, and awf keeps no record of it.

--no-fork opens the session itself: what you say stays with the agent, awf logs shows it, and the
next attempt resumes it. It is refused while the run is live; while it is open, no attempt starts
and an event waits, and once the harness exits a run with events is woken for it.
--session opens another session in the agent's place: a copy an earlier awf open made, as it is;
or one of the agent's earlier sessions, as its latest would be.
-p asks one question headless and prints the answer; the text is its argument, or stdin without
one. It runs as the agent's turns ran, without prompts, in its sandbox when it had one; on
claude, billed per token headless, it is refused unless the agent ran metered.
As the harness exits, awf prints the command that opens the same session again.

With --json, -p prints {"v": 1, "session", "forkedFrom"?, "reply", "again"}, or a refusal whose
code says why: usage, no-run, ambiguous, id, no-session, live, opened, unreachable, no-engine,
other-engine or internal-error. no-session is an agent with no session or operation to open;
live, --no-fork, or a sandboxed agent, on a running run, or a --no-fork whose session changed as
it held the run; opened, a run another awf open --no-fork holds, or a sandbox another awf open
has open; internal-error, a copy or a -p question that failed. A TUI has no JSON: --json without
-p is a usage error. Exits with the TUI's exit code, or 0 once -p printed its answer; 1 when
refused or failed; 2 on a usage error, or a -p or a TUI the agent's harness can't give; 3 when
the run or the agent's place could not be read, or awf itself failed.
